Sauvegarde de configuration

1Sauvegarder les volumes d'un namespace

Exporte et nettoie automatiquement tous les PV et PVC du namespace. Équivaut aux boucles kubectl + nettoyage manuel des manifestes.

Chemin sur la machine qui exécute l'outil. Le sous-dossier <namespace>/<horodatage> est créé automatiquement.

Restauration en masse

Recrée tous les namespaces supprimés du cluster actif () depuis leur dernière sauvegarde antérieure à l'instant de référence : namespace, PV/PVC, workloads, dépendances, Secrets (coffre déverrouillé), Volume Groups restaurés par HYCU s'ils ont disparu, applications stateless. Les namespaces encore présents sont ignorés : une application vivante se restaure depuis sa propre ligne. Exécution séquentielle et journalisée, reprise possible ; simulation obligatoire avant le réel.

2Protéger les données dans HYCU

L'export ci-dessus ne sauvegarde que les manifestes (la « recette » du restore). Les données vivent dans les Volume Groups Nutanix : seul HYCU les sauvegarde réellement. Ici, on associe les PVC du namespace aux Volume Groups HYCU, on assigne une politique, et on lance une sauvegarde.

Enregistrez la source HYCU (⚙ en haut à droite) pour activer cette section.

      🔒Mémoriser les connexions (chiffré)

      Option : enregistrer les identifiants saisis (et les kubeconfigs des clusters ajoutés) dans un coffre chiffré (hycu_secrets.enc), protégé par une phrase secrète maîtresse — jamais stockée. Par défaut, rien n'est écrit (RAM seulement), le choix le plus sûr.

      aucun coffre
      MD5 n'étant pas réversible, le coffre utilise un chiffrement par phrase secrète (PBKDF2-HMAC-SHA256 + scellé d'intégrité).
